# Debug Session: phone-screening-poll-race

- Status: [CLOSED]
- Goal: 定位电话确认页在批量录音处理中，已完成录音详情被轮询重绘打断的原因。
- Constraint: 先确认前端轮询与详情重渲染路径，再做最小修复；不扩展到无关功能。

## Hypotheses

1. 轮询会反复重建已打开的完成录音详情，导致字段点击和播放被打断。
2. 详情页播放状态与列表刷新共用渲染路径，轮询更新时会重挂载播放器。
3. 已完成录音在批量处理中被错误视为仍需刷新详情，导致界面跳动。
4. 轮询返回的最新数据会覆盖当前打开的详情浮层状态。

## Evidence

- 电话确认页的 `renderCallDetail({ preservePlayback: true })` 会在轮询后再次进入详情渲染流程。
- 当其他录音仍在处理时，已打开的完成录音详情页会被反复整页重建。
- 该重建会导致字段点击像被关闭、页面出现跳动，播放也会受影响。
- 已完成录音详情不再被轮询重建后，字段编辑与播放恢复正常。

## Conclusion

根因是电话确认页在批量处理中把轮询结果直接回灌到当前打开的完成录音详情，导致详情页被重复重建。修复后保留轮询刷新列表和状态，但不再重建已打开的详情浮层。

## Post-fix Verification

- 已完成录音详情在其他录音处理中保持稳定，不再被轮询打断。
- 字段点击和音频播放可持续使用。
- 问题属于“批量处理中，已完成条目被轮询重绘影响”的同类问题，后续可优先检查当前打开详情是否被轮询直接重建。
