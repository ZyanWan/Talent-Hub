# 并发与轮询竞态

状态：`[CLOSED]`

## 问题类型

对同一资源的并发访问或轮询重绘缺少串行化 / 「跳过已打开对象」的语义，导致竞态破坏已完成的 UI 状态或渲染结果。

## 表现

### 表现一：轮询重绘打断已打开的完成录音详情

- 电话确认页的 `renderCallDetail({ preservePlayback: true })` 会在轮询后再次进入详情渲染流程。
- 批量录音处理中，其他录音仍在处理时，已打开的完成录音详情被反复整页重建，字段点击像被关闭，音频播放也受影响。
- 属于「批量处理中已完成条目被轮询重绘影响」的同类问题，优先检查当前打开详情是否被轮询直接重建。

### 表现二：PDF 预览与后台预取并发访问 PDFium 失败

- 前端打开工作台时同时请求当前 PDF，并在后台预取其余 PDF，两条路径并发进入非线程安全的 PDFium 渲染路径。
- 串行渲染全部成功，并发渲染复现 PDFium 取页或位图渲染失败，有效 PDF 显示「此文件格式暂不支持预览」。
- 清理代码在位图创建失败时未考虑位图变量未初始化，抛出清理异常并遮蔽底层渲染异常。

## 根因

对已打开的详情浮层 / PDFium 渲染器的并发访问或轮询竞争缺少串行化或跳过已打开对象的语义，导致正常对象被竞态破坏或在渲染阶段失败。

## 修复

- 电话确认页保留轮询刷新列表和状态，但不再重建已打开的详情浮层。
- PDFium 预览渲染在进程内通过互斥锁串行执行。
- 页面、位图、图像和缓冲区按创建成功后的嵌套层级清理，保留真实渲染异常；不支持的文件类型与 PDF 渲染失败使用不同标题。

## 修复后验证

- 已完成录音详情在其他录音处理中保持稳定，字段点击和音频播放可持续使用。
- `python -m unittest tests.test_resume_preview` 通过；最近任务的 12 份 PDF 并发提交后全部完成预览渲染。
- 回归测试覆盖并发请求串行化和渲染失败清理。
