# Debug Session: modal-scroll-through

- Status: [CLOSED]
- Goal: 定位前端模态框打开后，滚轮仍能滚动背景页面的问题。
- Constraint: 统一修复公共模态框的背景滚动，不改变弹窗内部滚动、开合动画或各业务组件行为。

## Observations

- 页面根元素允许纵向滚动：`html` 使用 `overflow-y: auto`，`body` 的纵向 overflow 为 `visible`。
- 设置弹窗、任务记录抽屉、结果预览、简历工作台、AI 对比、电话详情和确认框均使用 `.preview-backdrop` 作为公共遮罩。
- `.preview-backdrop` 使用固定定位覆盖视口，但没有锁定根页面滚动。
- 在 1280 x 360 的浏览器视口中，页面高度为 520px；打开设置弹窗后，在遮罩空白处向下滚动，`window.scrollY` 从 0 变为 160。
- 弹窗内部的动态内容使用独立滚动容器，不依赖根页面滚动。

## Hypotheses

1. 设置弹窗内部滚动容器把滚动传递到了背景页面。
   - 支持证据：低高度视口中的设置内容可以独立滚动。
   - 冲突证据：在弹窗外的遮罩空白处滚动也能改变 `window.scrollY`。
2. 固定定位遮罩只阻止鼠标点击，不会自动禁止根页面滚动。
   - 支持证据：遮罩覆盖完整视口时，`html` 和 `body` 的 overflow 状态保持可滚动，背景滚动位置随滚轮变化。
   - 冲突证据：无。
3. 某个模态框组件遗漏了专用滚动锁。
   - 支持证据：所有模态框组件均未设置根页面 overflow。
   - 冲突证据：问题来自公共遮罩规则，逐个组件增加锁定会重复实现同一行为。

## Root Cause

公共遮罩只提供视觉覆盖和点击隔离，没有在遮罩挂载期间禁止根页面滚动。滚轮位于遮罩空白区域时，浏览器仍将滚动应用到可滚动的 `html`，造成背景页面滚动穿透。

## Fix

- 使用 `html:has(.preview-backdrop)` 在任意公共遮罩挂载期间将根元素 overflow 设为 `hidden`。
- 遮罩卸载后选择器自动失效，根页面恢复原有滚动规则。
- 保留弹窗内部滚动容器、开合动画和嵌套模态框行为。
- 项目现有样式已经使用 `:has()`，该修复不增加新的 CSS 兼容性要求。

## Post-fix Verification

- 在相同的 1280 x 360 浏览器视口中打开设置弹窗后，根元素 overflow 为 `hidden`。
- 在遮罩空白处向下滚动后，`window.scrollY` 保持为 0。
- 关闭设置弹窗后，根元素恢复为 `overflow-y: auto`，页面可以正常滚动。
- 未运行系统性测试或视觉测试。
