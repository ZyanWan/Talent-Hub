# Debug Session: resume-preview-pdfium-race

- Status: [CLOSED]
- Goal: 定位有效 PDF 简历显示“此文件格式暂不支持预览”的原因。
- Constraint: 仅修复 PDF 预览链路，不扩展其他文件格式的预览能力。

## Observations

- 最近任务的 12 份简历均为 PDF，文件大小和页数均未超过预览限制。
- 应用日志显示预览请求进入 `_render_pdf_preview()` 后在 PDFium 取页阶段报 `PdfiumError: Failed to load page`。
- 同一批 PDF 串行渲染全部成功，并发渲染时出现 PDFium 取页或位图渲染失败。
- 前端打开工作台时会同时请求当前 PDF，并在后台预取其余 PDF。

## Hypotheses

1. PDFium 被当前预览和后台预取并发调用，导致渲染状态冲突。
   - 支持证据：串行渲染成功，并发渲染复现失败；日志中多份有效 PDF 连续在同一渲染位置失败。
   - 冲突证据：无。
2. PDF 文件结构损坏。
   - 支持证据：日志中的底层错误是无法加载页面。
   - 冲突证据：相同文件串行渲染成功，筛选解析也已完成。
3. PDF 渲染组件缺失或页数超过上限。
   - 支持证据：这两类情况也会进入不可预览状态。
   - 冲突证据：日志已经进入 PDFium 取页，实际文件最多 3 页。

## Experiment

- 对最近任务中的同一批 PDF 分别执行串行和双线程渲染。
- 串行抽样 3 份全部成功；双线程渲染复现 PDFium 失败，并触发未初始化位图变量的清理异常。
- 结论：假设 1 成立，假设 2 和假设 3 排除。

## Root Cause

前端当前预览与后台预取会并发进入非线程安全的 PDFium 渲染路径，使有效 PDF 在取页或位图渲染阶段失败；清理代码还会在位图创建失败时遮蔽底层异常。

## Fix

- PDFium 预览渲染在进程内通过互斥锁串行执行。
- 页面、位图、图像和缓冲区按创建成功后的嵌套层级清理，保留真实渲染异常。
- 不支持的文件类型与 PDF 渲染失败使用不同标题，渲染失败保留具体错误原因。
- 回归测试覆盖并发请求串行化和渲染失败清理。

## Post-fix Verification

- `python -m unittest tests.test_resume_preview` 通过。
- 最近任务的 12 份 PDF 并发提交后全部完成预览渲染。
