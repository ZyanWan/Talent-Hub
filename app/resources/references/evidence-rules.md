# 证据规则

> 本文件是评估过程中的**内部思考工具框架**，用于指导你如何从简历中提取和判断证据。
> 这些规则是你的"思考方法"，而不是输出格式——最终的评估表只呈现判断和结论。

## 判断规则

1. 不允许仅凭岗位名称判断匹配。
2. 不允许把关键词本身当成证据，必须看上下文职责是否支持。
3. 不允许脑补简历没有写出的内容。
4. 简历未体现的信息，必须写“未体现”。
5. A类候选人必须有关键工作内容的明确证据。
6. B类用于定向电话确认，不是模糊备选池。
7. C类必须说明具体不匹配原因。
8. 模糊标准要转换成电话确认问题。
9. 必须先判断候选人做的对象是否匹配，再判断候选人的动作是否匹配。
10. 必须单独判断业务场景垂直性，不能用总年限替代相关年限。
11. 明确负向证据具有否决权，不能用通用优势抵消核心不匹配。
12. B类只用于“可能匹配但证据不足”，不能用于“已明确方向不匹配但履历看起来不错”。
13. 不允许把相邻行业、相邻产品、相邻客户类型自动视为可迁移；只有JD或用人部门样本明确接受时，才可进入B类确认。
14. 不允许用证书、工具、标准、流程关键词抵消对象或场景不匹配。

## 通用评估顺序

所有岗位评估必须按以下顺序执行，不得直接从关键词或岗位名称跳到结论：

1. 岗位本质：目标岗位真正解决什么问题，核心产出是什么。
2. 核心对象：候选人服务或处理的对象是否与岗位一致，例如产品、物料、客户、系统、渠道、人群、区域或业务线。
3. 业务场景：候选人所在行业链路、产品形态、客户类型、交付模式、组织环境是否与岗位垂直。
4. 边界校验：JD是否明确允许候选人的相邻行业、相邻产品或相邻职能迁移；如果没有明确允许，按不匹配处理。
5. 核心动作：候选人是否做过岗位真正需要的动作，而不是相邻岗位、支持岗位或下游交付动作。
6. 负责深度：候选人是主导、独立负责、协同、参与、支持、维护还是录入。
7. 闭环结果：候选人是否有从发现问题到推动解决再到结果复盘的证据。
8. 风险校验：稳定性、职业连续性、薪资、地点、层级、硬性条件是否存在风险。
9. 结论分档：只有前序证据支持时才给A；关键事实不清给B；核心对象、场景或动作明确不匹配给C。

## 通用证据框架

评估每份简历时，应尽量提取以下证据。简历没有写出的内容必须标注“未体现”。

| 证据类型 | 需要回答的问题 |
|---|---|
| 对象证据 | 候选人实际服务、处理或负责的对象是什么 |
| 场景证据 | 候选人处在什么业务模式、行业链路、客户类型或组织环境 |
| 动作证据 | 候选人实际做过哪些核心动作 |
| 深度证据 | 候选人是主导、独立负责、协同、参与还是支持 |
| 闭环证据 | 是否处理过异常、推进过项目、解决过问题并形成结果 |
| 结果证据 | 是否有金额、数量、转化率、交付率、留存率、周期、成本、效率等结果数据 |
| 工具证据 | 是否使用岗位相关系统、工具、方法或证书，并用于关键流程 |
| 协同证据 | 与哪些内部或外部角色协作，协作到哪一步 |
| 稳定性证据 | 最近几段工作时长、变动原因、职业方向是否连续 |
| 缺口证据 | 岗位关键要求中哪些未体现、模糊或矛盾 |
| 校准证据 | 已通过/未通过样本体现出的真实岗位边界是什么 |

## 通用防误判规则

- 不要用“岗位名相同”替代“职责相同”。
- 不要用“行业相同”替代“业务场景相同”。
- 不要用“相邻行业可迁移”替代“JD明确接受”。
- 不要用“同属硬件/同属互联网/同属制造/同属ToB”替代“核心对象一致”。
- 不要用“年限相同”替代“相关经验足够”。
- 不要用“全流程”替代“关键动作明确”。
- 不要用“管理、统筹、负责”替代“实际负责深度明确”。
- 不要用“大厂、知名公司、头部客户”替代“岗位匹配”。
- 不要用“项目很多”替代“项目相关”。
- 不要用“有数据”替代“数据口径有效”。
- 不要用“会工具”替代“用工具解决过岗位问题”。
- 不要用“沟通协调强”替代“专业能力匹配”。
- 不要用“认证/审核/测试/项目管理等通用动作相似”替代“产品对象和业务场景匹配”。
- 不要用相邻岗位动作替代目标岗位动作，例如售后交付、物流履约、运营支持、数据录入、行政协调等。
- 不要用“泛化动词+无具体宾语”的空洞描述替代具体证据；空洞描述不算证据。

## 通用负向信号

命中以下信号时必须降档、电话确认或直接不推进；先区分“简历未写”与“明确不符”：
未写的信息不构成不匹配，应走 B 核实；只有明确不符才直接不推进。

- 简历大量使用泛化词，但缺少具体对象、动作、结果和个人贡献。
- 职责看似丰富，但目标岗位的核心动作没有出现。
- 经验主要来自相邻岗位，而不是目标岗位本身。
- 核心对象不同，例如目标岗位要求A对象，候选人长期处理B对象。
- 场景垂直性弱，例如业务模式、客户类型、产品形态、交付链路与岗位差异明显。
- JD要求特定产品/行业时，候选人来自相邻硬件、相邻服务、相邻监管行业，但未体现目标对象经验。
- 近几段经历方向跳变明显，时间都很短且简历没有合理解释，完全可以判定为稳定性不足，不匹配。
- 最近一段工作时间很短，且无明确原因。
- 候选人层级明显高于或低于岗位要求；执行型岗位中，资历、年龄、管理经历明显超出且动机不清时直接C。
- 薪资、城市、通勤、工作强度或到岗时间与岗位明显不匹配。
- 量化成果很多，但和目标岗位核心产出关系弱。
- 项目描述完整，但候选人个人贡献不清。
- “参与、协助、配合”较多，“独立负责、主导、闭环”较少。

## A/B/C通用口径

- A类：核心对象匹配、业务场景垂直、关键动作明确、负责深度和闭环证据充分，且无明显稳定性、层级、薪资或硬性条件风险。
- B类：核心对象和场景大体相关，但关键动作、深度、结果或风险项不清楚，电话确认后可能改变结论；如果当前任务中B类也进入面试，必须写清“可面试但优先级低/带问题面试”。
- C类：核心对象、业务场景或关键动作明确不匹配；相关经验不足；或稳定性、层级、方向风险明显且简历无法解释。
- 不确定时不要硬给A；明确不匹配时不要放进B。
- 软性缺口（工具、证书、结果数字）不改变结论，写入备注即可；
- B 类按缺口影响分高/中/低：高=必须电话确认；中=邮件/问卷核实；低=备选池。

## 非相似性判断

- 不判断候选人与样例像不像。
- 不判断候选人之间像不像。
- 不要求新候选人与样例简历相同。
- 样例只能用于提取与岗位要求相关的证据维度。
- 候选人只需要在岗位要求的关键维度上提供足够证据。

## 符号说明

| 符号 | 含义 |
|---|---|
| ✓ | 完全匹配 / 具备该条件 |
| ！ | 部分匹配 / 不确定 / 需要验证 |
| ✗ | 不匹配 / 缺少该条件 |

## 评估原则

1. 客观性：基于简历中的事实信息，而非主观印象。
2. 系统性：按照岗位评估表逐项对比，不跳过关键证据项。
3. 可参照性：如有已通过样例，只提取与岗位要求相关的证据维度。
4. 多维度：综合考虑教育背景、工作经验、技能、薪资、稳定性和风险信号。
5. 可执行性：输出具体面试建议、电话确认问题和关注重点。

## 质量检查

- 是否讲清岗位本质
- 硬门槛是否只保留真正必要条件
- 是否把岗位要求转换成可从简历提取的证据项
- A/B/C规则是否足够具体，能重复执行
- 是否写出相似但错误的候选人类型
- 是否按对象匹配、场景垂直、动作证据、深度闭环、风险校验的顺序判断
- 是否识别相邻岗位、相似行业、相似动作但本质不匹配的候选人
- 是否避免把总年限、大厂、泛化量化数据或沟通协调能力当成核心匹配证据
- 是否按优先级解析PDF简历，而不是默认使用慢速OCR
- 是否把简历证据映射到评估表后再给结论
- 是否在有参考样例时只提取岗位相关证据维度
- 是否覆盖必备条件、加分项、岗位职责和薪资匹配
- 是否避免使用候选人相似度、感觉匹配、稀缺度等主观判断
- 电话确认问题是否询问具体经历、范围、数据和案例
