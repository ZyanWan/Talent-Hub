# Excel 候选人评估表输出规范（应用实现）

> 本文档描述 Talent-Hub 应用中候选人评估表（`.xlsx`）的实际生成与校验实现，基于 `app/pipeline.py`、`app/runtime/build_candidate_workbook.py`、`app/runtime/validate_workbook.py`、`app/runtime/workbook_contract.py` 的代码事实编写，非技能工作流说明。
> 工作簿的结构、字段、样式与安全约束由代码强制保证（统一维护在 `app/runtime/workbook_contract.py`），本文档是对实现契约的说明。

## 核心定位

Excel 评估表是面向招聘协作的**决策交付物**，不是评估时的思维过程展示板。

### 五张表的职责分层

| 工作表 | 职责 | 目标读者 | 使用频率 |
|---|---|---|---|
| **候选人总表** | **决策面板：结论+判定+风险+下一步动作** | HR/招聘方 | 每次必看 |
| **证据匹配表** | **后台支撑：详细证据记录供追溯和审计** | 需要深挖时查看 | 按需查看 |
| **电话确认问题** | **行动清单：只收录会改变结论的问题** | HR/面试官 | 约面/电联前看 |
| **筛选标准** | **评判依据：嵌入岗位规则防走样** | 评审/交接时参考 | 有争议时查阅 |
| **推荐名单（仅A类）** | **对外交付：仅 A 类候选人的约面名单与联系方式** | 用人部门 | 每次约面时直接使用 |

**主表原则**：HR 打开 Excel 第一眼看到的是"这个人行不行、为什么、下一步怎么做"。证据链细节藏在子表中，需要时才翻。推荐名单是唯一面向用人部门外发的表，只放结论与联系方式，不放证据链。

## 输出文件

```text
<任务数据目录>/候选人评估表.xlsx
```

评估任务每次运行都会重新生成该文件（`pipeline.py` `_run` 末尾），生成后必须通过结构校验才能交付。

## 生成流程

评估任务在全部候选人评估完成后，按以下顺序生成并校验工作簿（`pipeline.py` `_run`）：

1. `workbook_payload(criteria, evaluations)` 依据筛选标准与评估结果组装五张表的数据。**字段结构由代码固定**（见 `workbook_contract.py`），大模型输出只填充内容值，不参与决定表结构与列。
2. `build_workbook(payload, output)`（`app/runtime/build_candidate_workbook.py`）生成 `.xlsx`：以临时文件写入后原子替换，避免中断产生损坏文件。
3. `validate_workbook_detailed(output)`（`app/runtime/validate_workbook.py`）做结构与安全检查。存在**阻塞性错误**时抛异常，任务以失败告终、不交付；仅存在**样式类警告**时警告并入任务 errors 提示，不阻断交付。
4. 校验通过后任务置为 `completed`，界面提供工作簿下载。

校验通过仅代表文件满足结构契约，不验证筛选标准或 A/B/C 结论的业务正确性。

## 固定数据契约（`app/runtime/workbook_contract.py`）

- **必需工作表**（`REQUIRED_SHEET_NAMES`，顺序固定）：候选人总表、证据匹配表、电话确认问题、筛选标准、推荐名单（仅A类）。
- **结论枚举**（`CONCLUSION_VALUES`）：只允许 `A优先约面`、`B电话确认`、`C不推进` 三个完整值。
- **每表核心字段**（`CORE_FIELDS_PER_SHEET`）与默认列（`DEFAULT_HEADERS_PER_SHEET`）见下节；校验器允许额外扩展列，但核心字段不得缺失。
- **行数下限**（`MIN_DATA_ROWS_PER_SHEET`）：总表、证据匹配表、筛选标准至少 1 行；电话确认问题、推荐名单允许只有表头（无 B 类/无 A 类时）。
- **行键字段**（`ROW_KEY_FIELD_PER_SHEET`）：总表/证据表/电话表/推荐名单以"候选人"为键，筛选标准以"模块"为键。
- **筛选标准模块**（`STANDARD_MODULES`）：岗位本质、硬性门槛、A类规则、B类规则、C类规则、否决信号、相似错误类型，七项必须全部出现。

## 工作表一：候选人总表（决策面板）

> 每位候选人一行，呈现判断结果而非推理过程。

字段（核心字段加粗）：

| 字段 | 回答的决策问题 | 填写要求 |
|---|---|---|
| **推荐顺序** | 谁优先？ | 正整数，A 类优先；必须以 JSON 数字写入 |
| **候选人** | 是谁？ | 姓名；未知则写文件名 |
| **结论** | 能不能推进？ | A优先约面 / B电话确认 / C不推进 |
| **一句话判定** | 为什么给这个结论？ | **基于综合判断的一句结论摘要**，说明核心匹配点或不匹配原因，不列举证据来源。例："4年消费电子全流程认证经验，行业和动作完全匹配。" |
| 当前/最近公司 | 在哪？ | 简历证据或"未体现" |
| 当前/最近岗位 | 做什么？ | 简历证据或"未体现" |
| 核心优势摘要 | 强在哪？ | 与岗位直接相关的 1-2 条优势结论，写"有什么优势"而非"哪里体现了优势" |
| **关键风险/Blocker** | 弱点或否决项是什么？ | 影响推进的具体风险；C 类直写不匹配点 |
| **下一步动作** | 该做什么？ | 约面 / 电话确认XX后再定 / 暂不推进因XX |
| 来源文件 | 评估对象 | 对应简历文件名 |
| 证据校验提示 | 校验结果 | 引文未通过原文校验等程序化提示 |
| 备注 | 其他需关注的信息 | 期望薪资、到岗时间、稳定性线索等 |

### 字段填写反模式（禁止）

- ❌ "候选人特点：证据链齐全，简历中工作经历第2段可以证明其具备CE认证能力"
- ❌ "核心优势：从简历中可以看出候选人有丰富的FCC认证经验（详见第3段）"
- ❌ "关键风险：虽然年限略低但从项目经历来看能力尚可"

### 字段填写正模式

- ✅ "一句话判定：4年消费电子全流程认证经验，行业和动作完全匹配"
- ✅ "核心优势摘要：独立负责过欧美多国认证项目，对接莱茵TUV等机构"
- ✅ "关键风险：年限2.5年略低于3年门槛"

## 工作表二：证据匹配表（后台支撑）

> 详细记录每位候选人的对象、场景、动作、深度、闭环等证据细节，供追溯、审计和解释结论时使用。

字段：候选人、对象证据、场景垂直性、核心动作证据、负责深度、闭环证据、工具/系统/证书、规模/结果、稳定性、证据充分度（高/中/低）。每格格式为 `[状态] 摘要；原文：逐字引文（位置）`，状态取值 `匹配|待确认|不匹配|未体现`；有引文才带"原文："，有位置信息才带括号。

## 工作表三：电话确认问题（行动清单）

> 只收录会影响 A/B/C 结论的问题，每条对应一个可能改变分类的行动项。

字段：候选人、优先级（高/中/低）、确认焦点、问题、当前证据、确认后影响（如 B→A 或 B→C）。

校验关联：每位 B 类候选人在此表**至少一个问题**；此表不应出现 B 类之外的候选人（样式警告）。

## 工作表四：筛选标准（评判依据）

> 把生成筛选标准嵌入工作簿，防止评估表脱离标准单独流转后失真。

字段：模块、内容、备注。模块必须覆盖岗位本质、硬性门槛、A类规则、B类规则、C类规则、否决信号、相似错误类型。

## 工作表五：推荐名单（仅A类）（对外交付）

> 面向用人部门直接使用的约面名单，只收录 A 类候选人，不暴露内部证据链。

字段：推荐顺序（仅对 A 类从 1 重新编号）、候选人、结论（固定为 A优先约面）、一句话判定、联系电话、邮箱（从简历原文提取，未出现显示「无」）。

校验关联：总表中每位 A 类候选人必须在此表有一行；此表不得出现 B/C 类或总表之外的候选人。联系方式非必填，提取不到时显示「无」，不得编造。

## 样式规则（`build_candidate_workbook.py`）

1. 首行加粗，浅色底纹（`HEADER_FILL_COLOR = D9EAF7`）。
2. 所有工作表冻结首行（`FREEZE_PANES = A2`）。
3. 所有工作表开启自动筛选。
4. `结论`列颜色区分：A 浅绿 `D9EAD3`、B 浅黄 `FFF2CC`、C 浅红 `F4CCCC`。
5. 不合并单元格。
6. 不使用公式、单元格超链接、宏/VBA 或外部连接。
7. 单元格自动换行，列宽按内容自适应（12–45 字符范围）。

## 单元格安全与类型

1. 所有字符串都按字面量写入（`data_type="s"`）。即使内容以 `=`、`+`、`-`、`@` 或空白字符开头，也不得生成 Excel 公式。
2. JSON 中的整数、浮点数和布尔值保留为 Excel 原生类型，不统一转成字符串；NaN/Infinity 直接报错。
3. 数字样字符串保持文本（编号、手机号、`00123` 等）。
4. 扁平列表使用换行展示；字典或嵌套结构使用标准 JSON 文本展示。
5. 校验器在打开文件前先检查压缩包（`inspect_archive`）：发现 VBA/宏、外部链接、外部数据连接或外部关系即报错；随后逐单元格检查公式（`data_type == "f"`）与超链接。

## 校验清单（`validate_workbook.py` 强制项）

1. 文件存在且为 `.xlsx`，可正常打开。
2. 五张必需工作表齐全、顺序固定、均可见，活动表为候选人总表。
3. 每表核心表头齐全，无重复表头，数据行不缺行键字段。
4. 主表结论为合法枚举值；推荐顺序为正整数且不重复。
5. A/B/C 结论可追溯到证据匹配表或筛选标准（候选人与模块全覆盖）。
6. 主表无证据链语言（如"简历XX段证明""证据显示"）——此为填写要求，由生成方保证。
7. 开启筛选、冻结首行；无合并单元格。
8. 每位 B 类候选人至少有一条电话确认问题。
9. 推荐名单仅含 A 类且覆盖全部 A 类候选人。
10. 工作簿不包含公式、超链接、宏或外部连接。
