# Excel候选人评估表输出规范

## 核心定位

Excel评估表是面向招聘协作的**决策交付物**，不是你评估时的思维过程展示板。

### 四张表的职责分层（重要）

| 工作表 | 职责 | 目标读者 | 使用频率 |
|---|---|---|---|
| **候选人总表** | **决策面板：结论+判定+风险+下一步动作** | HR/招聘方 | 每次必看 |
| **证据匹配表** | **后台支撑：详细证据记录供追溯和审计** | 需要深挖时查看 | 按需查看 |
| **电话确认问题** | **行动清单：只收录会改变结论的问题** | HR/面试官 | 约面/电联前看 |
| **筛选标准** | **评判依据：嵌入岗位规则防走样** | 评审/交接时参考 | 有争议时查阅 |

**主表原则**：HR打开Excel第一眼看到的是"这个人行不行、为什么、下一步怎么做"。证据链细节藏在子表中，需要时才翻。

## 输出文件

```text
<ResumeFolder>/候选人评估表.xlsx
```

如需保留长文本解析或单份详细报告，另行生成：

```text
<ResumeFolder>/候选人解析与评估明细.md
```

## 生成方式

优先使用 `scripts/build_candidate_workbook.py` 生成 `.xlsx`。该脚本支持动态字段——AI根据具体任务决定字段组成，脚本负责技术实现。

```bash
python scripts/build_candidate_workbook.py --input-json <ResumeFolder>/candidate_rows.json --output <ResumeFolder>/候选人评估表.xlsx
python scripts/validate_workbook.py <ResumeFolder>/候选人评估表.xlsx
```

JSON 顶层必须包含四个工作表名：`候选人总表`、`证据匹配表`、`电话确认问题`、`筛选标准`。核心字段固定，AI 可以根据任务增加扩展字段，但不得删除或替换核心字段。

## 固定数据契约

| 工作表 | 核心字段 | 行要求 |
|---|---|---|
| 候选人总表 | 推荐顺序、候选人、结论、一句话判定、关键风险/Blocker、下一步动作 | 至少一位候选人 |
| 证据匹配表 | 候选人、对象证据、场景垂直性、核心动作证据、负责深度、闭环证据、证据充分度 | 每位总表候选人至少一行 |
| 电话确认问题 | 候选人、优先级、确认焦点、问题、当前证据、确认后影响 | 没有 B 类时可以只有表头；每位 B 类至少一题 |
| 筛选标准 | 模块、内容 | 必须包含岗位本质、硬性门槛、A类规则、B类规则、C类规则、否决信号、相似错误类型 |

`结论`只允许以下三个完整值：`A优先约面`、`B电话确认`、`C不推进`。不得使用前缀相似但含义不明确的值。

`推荐顺序`必须在输入 JSON 中写为正整数，不要写成字符串。相同工作簿中的推荐顺序不得重复。

## 工作表一：候选人总表（决策面板）

> **这是HR最常看的表。每位候选人一行，呈现判断结果而非推理过程。**

### 设计原则

- **结论导向**：每个字段回答一个决策问题（能不能约？为什么？风险是什么？怎么做？）
- **不呈现证据链**："简历中XXX证明了YYY"这类描述属于证据匹配表，不属于这里
- **一句话原则**：能用一句说清的不写一段
- **行动收口**：看完一行就知道下一步是约面、确认还是放弃

### 字段说明

以下字段包含固定核心字段和常用扩展字段。AI 可以根据岗位增加扩展字段，但不得删除固定数据契约中的核心字段：

| 字段 | 回答的决策问题 | 填写要求 |
|---|---|---|
| 推荐顺序 | 谁优先？ | 正整数，A类优先；必须以 JSON 数字写入 |
| 候选人 | 是谁？ | 姓名；未知则写文件名 |
| 结论 | 能不能推进？ | A优先约面 / B电话确认 / C不推进 |
| 一句话判定 | 为什么给这个结论？ | **基于综合判断的一句结论摘要**，说明核心匹配点或不匹配原因。不要列举证据来源。例："4年消费电子全流程认证经验，行业和动作完全匹配。" |
| 当前/最近公司 | 在哪？ | 简历证据或未体现 |
| 当前/最近岗位 | 做什么？ | 简历证据或未体现 |
| 核心优势摘要 | 强在哪？ | 与岗位直接相关的1-2条优势结论。写"有什么优势"而非"哪里体现了优势"。例："独立负责过欧美多国认证项目"，而不是"简历第3段提到主导了CE认证..." |
| 关键风险/Blocker | 弱点或否决项是什么？ | 影响推进的具体风险。如果是C类的否决原因，直写不匹配点。例："行业为充电桩非消费电子"而非"虽然候选人在充电桩领域有丰富经验但..." |
| 下一步动作 | 该做什么？ | 约面 / 电话确认XX后再定 / 暂不推进因XX |
| 备注 | 其他需关注的信息 | 期望薪资、到岗时间、稳定性线索等 |

### 字段填写反模式（禁止）

- ❌ "候选人特点：证据链齐全，简历中工作经历第2段可以证明其具备CE认证能力"
- ❌ "核心优势：从简历中可以看出候选人有丰富的FCC认证经验（详见第3段）"
- ❌ "关键风险：虽然年限略低但从项目经历来看能力尚可"

### 字段填写正模式

- ✅ "一句话判定：4年消费电子全流程认证经验，行业和动作完全匹配"
- ✅ "核心优势摘要：独立负责过欧美多国认证项目，对接莱茵TUV等机构"
- ✅ "关键风险：年限2.5年略低于3年门槛"

## 工作表二：证据匹配表（后台支撑）

> **详细记录每位候选人的对象、场景、动作、深度、闭环等证据细节。供追溯、审计和解释结论时使用。**

此表记录评估过程中的**中间判断依据**，是主表结论的支撑材料。HR日常浏览不需要看这张表，但在需要解释"为什么给A/C"或审计评估过程时使用。

### 推荐字段

| 字段 | 说明 |
|---|---|
| 候选人 | 与总表一致 |
| 对象证据 | 候选人实际负责的对象及匹配状态 |
| 场景垂直性 | 行业链路/业务模式/客户类型及匹配状态 |
| 核心动作证据 | 与岗位关键动作相关的经历及匹配状态 |
| 负责深度 | 主导/独立负责/协同/参与/支持 |
| 闭环证据 | 异常处理/问题解决/结果复盘证据 |
| 工具/系统/证书 | 岗位相关工具和证书 |
| 规模/结果 | 量化数据及口径 |
| 稳定性 | 工作连续性和方向变化 |
| 证据充分度 | 高/中/低 |

---

## 工作表三：电话确认问题（行动清单）

> **只收录会影响A/B/C结论的问题。每条问题对应一个可能改变分类的行动项。**

| 字段 | 说明 |
|---|---|
| 候选人 | 与总表一致 |
| 优先级 | 高/中/低 |
| 确认焦点 | 对象/场景/动作/深度/薪资/稳定性等 |
| 问题 | 要求候选人回答的具体事实 |
| 当前证据 | 简历已有信息或未体现 |
| 确认后影响 | 可能的分类变化（如B→A/B→C） |

---

## 工作表四：筛选标准（评判依据）

> **把第1步生成的筛选标准嵌入工作簿，防止评估表脱离标准单独流转后失真。**

| 字段 | 说明 |
|---|---|
| 模块 | 岗位本质/硬性门槛/A类规则/B类规则/C类规则/否决信号/相似错误类型 |
| 内容 | 具体规则内容 |
| 备注 | 适用说明 |

---

## 样式要求

1. 首行加粗，浅色底纹
2. 所有工作表冻结首行
3. 所有工作表开启自动筛选
4. `结论`列颜色区分：A浅绿、B浅黄、C浅红
5. 不合并单元格
6. 不使用公式、单元格超链接、宏/VBA或外部连接

## 单元格安全与类型

1. 所有字符串都按字面量写入。即使内容以 `=`、`+`、`-`、`@` 或空白字符开头，也不得生成 Excel 公式。
2. JSON 中的整数、浮点数和布尔值保留为 Excel 原生类型，不得统一转换成字符串。
3. 数字样字符串保持文本，例如编号、手机号、`00123` 和未声明类型的日期字符串。
4. 扁平列表使用换行展示；字典或嵌套结构使用标准 JSON 文本展示。
5. 生成脚本不支持输入公式；校验器发现任何公式、超链接、宏或外部连接时必须报错。

## 脚本与字段的关系

`build_candidate_workbook.py` 的作用：
- 提供**生成xlsx的技术实现**（创建工作簿、写入数据、设置样式）
- 接受 JSON 输入，保证四张工作表和核心字段契约，允许增加扩展字段
- `sample_payload()` 提供满足核心契约的完整示例，AI 可以在核心字段之外增加扩展字段

AI的职责：
- 在核心字段之外，根据具体任务决定每张表需要增加哪些字段
- 决定主表的字段粒度和表述角度
- 确保主表是决策面板、子表是后台支撑

## 质量检查

1. 文件路径正确且可打开
2. 至少包含上述四张工作表
3. 主表包含"结论"和"一句话判定"
4. A/B/C结论能追溯到证据匹配表或筛选标准
5. 主表无证据链语言（如"简历XX段证明""证据显示"）
6. 开启筛选、冻结首行
7. 每位 B 类候选人至少有一条电话确认问题
8. 推荐顺序为唯一正整数，重新打开工作簿后仍为数字类型
9. 工作簿不包含公式、超链接、宏或外部连接

`validate_workbook.py` 只校验上述可机器判断的结构与安全规则。它不能判断简历事实是否真实、证据是否足以支持结论、筛选标准是否合理，或 A/B/C 业务判断是否正确。
